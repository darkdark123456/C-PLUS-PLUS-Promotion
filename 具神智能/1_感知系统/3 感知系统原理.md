# 感知系统入门


感知系统通过各种传感器获取机器人自身状态和外部环境信息，为运动控制、导航定位、人机交互和智能决策提供数据支持。



机器人感知系统主要包括：

| 分类 | 代表传感器 | 主要作用 |
| --- | --- | --- |
| 姿态与运动感知 | IMU、编码器 | 获取机器人自身运动状态 |
| 环境感知 | 相机、LiDAR、毫米波雷达 | 获取外部环境信息 |
| 接触感知 | 力/力矩传感器、触觉传感器 | 感知机器人与环境交互 |
| 定位导航 | GPS、RTK、UWB、里程计 | 确定机器人位置 |

## 传感器介绍
机器人常用传感器主要包括：

+ IMU（惯性测量单元）
+ 相机（Camera）
+ 激光雷达（LiDAR）
+ 力/力矩传感器（Force/Torque Sensor）
+ GPS、RTK、UWB等定位传感器

不同传感器负责获取不同维度的信息，机器人通常需要多个传感器融合，实现完整环境理解。

## I2C 协议(扩展了解）
可以把 **I²C** 理解成“**一根数据线轮流说话 + 一根时钟线负责打节拍**”。人类居然花了几十年把“轮流说话”标准化成总线协议，但它确实很好用。

### **I²C 核心**
<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/27211935/1789632802213-245135d8-a128-4e97-95f3-69d3c0066c67.png)

+ **SCL**：时钟线，一般由主机 MCU 产生时钟
+ **SDA**：数据线，地址、命令、数据都走它
+ **VCC + 上拉电阻**：SCL、SDA 通常都需要上拉电阻



### **它是全双工还是半双工**
:::tips
**I²C 是半双工通信。**

原因非常简单：它只有 **一根 SDA 数据线**。

## SPI 协议(扩展了解)

>

### **SPI 四根信号线**
SPI 最核心的是四根线：

** SCK（Serial Clock）**

序列时钟线



** MOSI（Master Out Slave In）**

主机输出，从机输入。



**MISO（Master In Slave Out）**

主机输入，从机输出。



** CS / SS（Chip Select）**

片选信号。

作用：**选择哪个从设备通信。**

其它设备保持静默。

# ****视觉传感器
视觉传感器是机器人获取外部环境信息最重要的传感器之一，能够获取物体的颜色、纹理、形状、位置及运动信息，是计算机视觉（Computer Vision）和视觉语言动作模型（Vision-Language-Action，VLA）的核心输入来源。

常见视觉传感器包括：



## 单目相机（Monocular Camera）
单目相机只有一个摄像头，可获取二维彩色图像（RGB）。



<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/27211935/1789713423975-ac1f90e2-0828-4b79-b0fd-e90eef3accb3.png)

**特点**

+ 成本低、结构简单
+ 分辨率高
+ 信息量丰富
+ 无法直接获取深度信息

通常需要结合：

+ 深度学习
+ 多帧视觉
+ SLAM

恢复三维信息。

**典型应用**

+ 图像分类
+ 目标检测
+ 语义分割
+ 人脸识别
+ VLA输入
+ 手眼标定



## 双目相机（Stereo Camera）
双目相机由左右两个摄像头组成，模拟人眼视觉。

通过计算左右图像之间的**视差（Disparity）**，即可计算目标距离。



<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/27211935/1789713595772-e9ddc8c3-13fe-45f3-a06c-fbf146ef9969.png)



**特点**

+ 可直接恢复三维深度
+ 不依赖主动发光
+ 深度精度受纹理影响较大
+ 算法计算量较高

**典型应用**

+ 三维重建
+ 障碍物检测
+ 视觉SLAM
+ 自动驾驶
+ 服务机器人



## RGB-D 相机（Depth Camera）
RGB-D 相机能够同时获取：

+ RGB彩色图像

常见深度获取方式包括：

# 传感器数据的共同特点
机器人系统通常需要依靠多种传感器获取环境信息和自身状态，例如 **IMU、Camera、LiDAR、GPS、编码器、力传感器** 等。虽然不同传感器的测量原理、数据形式和应用场景不同，但其输出数据通常具有一些共同特点。

这些特点直接影响机器人感知、定位、建图和控制系统的性能。因此，在进行多传感器融合之前，需要对传感器数据进行预处理，使其满足系统使用要求。

机器人传感器数据主要具有以下三个共同特点：

1. **存在噪声（Noise）**
2. **时间不一致（Time Synchronization Problem）**
3. **空间坐标不统一（Coordinate Frame Difference）**

**环境干扰（Environmental Disturbance）**

环境因素会影响传感器测量结果。

例如：

+ Camera 受到光照变化影响
+ LiDAR 受到雨雾、反射物影响
+ GPS 受到建筑物遮挡影响



**电子噪声（Electronic Noise）**

传感器内部电子元件会产生随机误差，例如：

+ 电路噪声
+ 信号传输误差
+ 模数转换误差（ADC Error）



**机械振动（Mechanical Vibration）**

机器人运动过程中：

### 控制不稳定
机器人控制系统依赖传感器反馈：

<!-- 这是一张图片，ocr 内容为： -->

噪声过大会导致：

+ 电机抖动
+ 机械臂运动不稳定

因此需要进行滤波处理。

:::info
**滤波**是指：**从包含噪声的信号中提取有用信息，减少或去除不需要的干扰，使数据更加平滑、准确。**

简单来说：

**滤波 = 去除噪声，保留真实信号。**

:::

## 时间同步 (**Time Synchronization)**
### 时间同步问题
现代机器人通常同时使用多个传感器：

例如：

| 传感器 | 数据 |
| --- | --- |
| IMU | 角速度、加速度 |
| Camera | 图像 |
| LiDAR | 三维点云 |
| GPS | 位置 |


但是不同传感器：

+ 采样频率不同
+ 时间戳来源不同
+ 数据传输延迟不同

例如：

<!-- 这是一张图片，ocr 内容为： -->

+ Camera 数据可能来自过去
+ IMU 数据可能来自当前

导致融合误差。

## 坐标系统一（Coordinate Frame Alignment）
###  坐标系问题
机器人上的不同传感器安装位置不同，因此每个传感器都有自己的坐标系。

例如：

<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/27211935/1789974514447-e411d3aa-8cab-46fc-87af-5645b11a1e08.png)

不同坐标系之间：

+ 原点不同
+ 方向不同

因此传感器数据不能直接融合。



###  常见坐标系
**Camera 坐标系 ( 相机坐标系  )**

相机标准约定（针孔相机模型）

:::tips
+ 原点：**相机光心**（镜头内部）
+ X 轴：图像水平向右
+ Y 轴：图像垂直向下
+ Z 轴：镜头向前（相机拍摄朝向，深度方向）
+ 输出：图像像素，可反推三维空间点
+ 用途：图像处理、目标检测、视觉观测

:::



**LiDAR 坐标系 ( 激光雷达坐标系  )**

不同厂商略有差异，通用机械雷达惯例

:::tips
+ **原点：激光雷达几何中心**
+ **X 轴：雷达正前方**
+ **Y 轴：雷达左侧**
+ **Z 轴：雷达向上**
+ **输出：三维点云，每个点 **<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/27211935/1789975826459-49eef986-9220-4a50-9710-c7dbf43288db.png)**，代表空间物体位置**
+ **用途：三维建图、障碍物检测、距离测量**

:::



**重点：相机 Z 向前，LiDAR X 向前！坐标轴定义完全不一样，拿到的点云不能直接贴到图像上，必须坐标变换。**

+ 障碍物检测



**IMU 坐标系( 惯性测量单元坐标系  )**

:::tips
+ **原点：IMU 芯片物理中心**
+ **X/Y/Z：芯片硬件丝印定义，由硬件出厂确定**
+ **输出：三轴加速度、三轴角速度，积分得到姿态角度**
+ **用途：姿态解算、运动估计，补偿视觉 / 雷达短时失效**

**IMU 不输出空间位置，输出的是运动变化量，数据是相对自身 IMU 坐标系。**

:::

用于描述：

+ 加速度
+ 角速度
+ 姿态变化





** Base Link 机器人基坐标系（本体坐标系）  **

机器人统一参考坐标。



:::tips
+ 原点：机器人底盘中心 / 几何中心（人为规定）
+ X：机器人前进方向
+ Y：机器人左侧
+ Z：竖直向上
+ ✨作用：**机器人本体统一参考基准**
+ 用途：运动控制、底盘速度指令、局部导航规划

相机、LiDAR、IMU 全部通过外参变换对齐到 base_link，所有传感器数据统一到本体坐标系后，才可以互相融合。

:::



用于：

+ 运动控制
+ 导航规划

---

**世界坐标系（World） （全局坐标系）  **

描述机器人在环境中的绝对位置。



:::tips
+ 原点：环境固定原点（建图起点 / GPS 原点，固定不动，不随机器人移动）
+ X/Y/Z：全局固定方向
+ 用途：构建地图、记录机器人绝对位姿、GPS 定位、全局路径导航

base_link 相对于 world 会不断变化；机器人走到哪，base_link 就在 world 里面得到一组坐标。

:::



用于：

+ 地图
+ GPS
+ 全局导航

### 外参标定（Extrinsic Calibration）
为了实现不同传感器数据融合，需要计算传感器之间的位置关系。

:::tips
外参 = 两个传感器坐标系之间固定的**相对位置姿态** 包含两部分：

1. **旋转 R**：坐标轴朝向差（谁偏左、偏右、倾斜多少）
2. **平移 t**：两个传感器原点之间的空间距离偏移

:::

**举实例：相机 → base_link**

相机装在机器人底盘上：

1. 相机光心不在底盘中心，两者有几米 / 厘米偏移 → 这部分就是**平移 t**
2. 相机 Z 轴朝前，base_link 是 X 轴朝前，坐标轴朝向不一样，还有可能相机微微向下倾斜 → 这部分就是**旋转 R**

### 总结
机器人传感器数据虽然来源不同，但通常具有三个共同问题：

| 问题 | 解决方法 | 目的 |
| --- | --- | --- |
| 存在噪声 | 滤波算法 | 提高数据可靠性 |
| 时间不一致 | 时间同步 | 保证数据描述同一时刻 |
| 坐标不同 | 外参标定与坐标转换 | 保证空间一致性 |


完整的数据处理流程：

```plain
传感器采集

      ↓

滤波降噪

      ↓

时间同步

      ↓

坐标系统一

      ↓

多传感器融合

      ↓

感知 / 定位 / 建图 / 控制
```

因此，**滤波解决数据质量问题，时间同步解决时间一致性问题，坐标系统一解决空间一致性问题，三者共同构成机器人多传感器融合的基础。**
