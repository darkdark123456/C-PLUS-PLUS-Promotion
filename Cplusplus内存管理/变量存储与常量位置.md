# 变量何时获得内存，常量存在哪里

整理自一次关于 `static` 成员、`constexpr` 常量、栈帧分配的讨论。
结论先行：**“分配存储”和“初始化”是两件事**，而且常量多数情况下根本不存在于任何数据内存中。

---

## 1. 一张总表

| 变量种类 | 存到哪 | **何时获得内存** | 初值 |
| --- | --- | --- | --- |
| 非静态成员 `int a;` | 和宿主对象同一块内存 | **对象创建时** | 初始化列表 / 默认初始化 |
| 局部变量 `int x;` | 栈 | **函数入口**（prologue 预留整帧） | 声明点；可能被优化进寄存器 |
| 局部静态 `static int s;` | `.bss` / `.data` | **程序加载时**（地址链接期固定） | 首次执行到那行才初始化（线程安全 guard） |
| 静态成员 `static int A::a;` | `.bss` / `.data` | **程序加载时** | 零初始化；动态初始化在 `main` 前 |
| 全局变量 | `.data` / `.bss` | **程序加载时** | 同上 |
| 命名空间常量 `const int k = 5;` | `.rodata`（取地址才有） | 加载时 | 编译期常量，常被折叠成立即数 |
| `constexpr` 变量 | 通常**没有存储** | 不分配 | 编译期求值 |
| 字符串字面量 | `.rodata` | 加载时 | 编译期 |
| `enum` / `#define` | **无** | 不分配 | 纯编译期 |
| `new` 出来的对象 | 堆 | **运行时 `new` 那一刻** | 构造函数 |
| `thread_local` | TLS 段 | **线程创建时** | 线程启动 / 首次使用 |

### 三个概念别混

| 概念 | 含义 |
| --- | --- |
| 分配存储（allocation） | 对象占的字节存在（栈 / 堆 / 静态区） |
| 初始化（initialization） | 往这些字节里写第一个有效值 |
| 未初始化 | 字节在，但内容不确定 → 读它 = 未定义行为 |

## 2. 逐类说明

### 2.1 非静态成员：跟着对象走，自己从不单独分配

```cpp
class A { int a; };
A  x;            // x 的内存里就含 a（偏移 0，4 字节）
A* p = new A;    // a 在堆上那块 sizeof(A) 里
```

- 类里那行 `int a;` 是**成员声明**，不分配独立存储
- 不能也不需要在类外定义：`int A::a;` 对非静态成员是编译错误
- `sizeof(A)` 编译期就确定 → 布局不是运行时算的
- 初始化靠初始化列表或默认成员初始化器（C++11）

### 2.2 局部变量：函数入口统一预留

```asm
f:
    push rbp
    mov  rbp, rsp
    sub  rsp, 32              ; ← 所有局部变量一次腾出
    mov  dword ptr [rbp-4], 5
```

不是每条声明一条指令，而是**进函数时整帧预留**。
`-O2` 下若没取地址，可能直接进寄存器，内存里根本不存在：

```asm
f:
    mov eax, 4                ; p 被完全消掉，只剩结果
```

### 2.3 局部静态：存储早就有，初始化才第一次执行

```cpp
void f() {
    static int s = init();    // 存储在 .bss/.data，加载时就有
                              // init() 只在第一次执行到这行时调用
}
```

C++11 起带线程安全 guard（`__cxa_guard_acquire` / `release`），
所以“分配”和“初始化”在这里是明确分开的两个时刻。

### 2.4 静态成员：地址在链接期就固定

```cpp
class A { static int a; };
int A::a;          // 定义 → .bss（未初始化）
int A::a = 42;     // 定义 + 初始化 → .data
```

- 文件里**不占空间**（`.bss` 只记录大小），加载时由内核清零映射
- `&A::a` 是编译期常量，所以静态成员不可能被放进寄存器
- 动态初始化在 `main` 之前完成
- C++17 起可写 `inline static int a = 0;`，类内即定义，无需类外补

### 2.5 全局变量

```cpp
int g1 = 42;    // .data，真占文件 4 字节
int g2;         // .bss，不占文件，加载时清零
```

### 2.6 常量

```cpp
const int       k = 5;       // 内部链接；取地址才落进 .rodata
constexpr int   K = 10;      // 通常完全折叠，无存储
static const int M = 3;      // 类内：没有存储，除非 ODR 使用
const char*     s = "hi";    // "hi" 在 .rodata
```

是否占内存，取决于**有没有把它当对象用**（取地址、绑引用、传引用）。
只当值用：

```asm
mov eax, 5      ; 没有任何内存访问
```

### 2.7 堆对象

```cpp
A* p = new A;   // 这一刻 malloc；之前什么都没有
```

### 2.8 thread_local

每个线程一份，存在 TLS 段，**线程创建时**随线程栈一起建立；
函数内的 `thread_local` 还有首次初始化的 guard。

## 3. 进程内存布局

```
高地址
┌─────────────┐  ← 程序加载时映射
│   栈 stack   │  局部变量、函数参数（运行时按帧伸缩）
├─────────────┤
│     ↓       │
│     ↑       │
├─────────────┤
│  堆 heap     │  new / malloc（运行时增长）
├─────────────┤
│  .bss        │  未初始化全局/静态（不占文件，加载时清零）
├─────────────┤
│  .data       │  已初始化全局/静态（占文件）
├─────────────┤
│  .rodata     │  常量、字符串字面量（只读）
├─────────────┤
│  .text       │  代码（立即数常量也在这里）
└─────────────┘
低地址
```

`.data` / `.bss` / `.rodata` 三块在 **`main` 运行之前**就已映射完毕，
这就是“静态存储期”的含义。

## 4. 常量到底存在哪（constexpr 专题）

`constexpr` 的常量**不占数据内存**，它被“编译进指令”了。

```cpp
constexpr int K = 42;
int f() { return K; }
```

```asm
f:
    mov eax, 42      ; 42 是指令字节的一部分，属于 .text
    ret
```

x86 的 `mov eax, imm32` 编码为 `B8 2A 00 00 00`，
`0x2A` 就是 42，跟着代码段一起存在可执行文件里。
寄存器只是运行时**临时搬运**它，不是存储位置。

### 4.1 三个去处

| 情况 | 常量在哪 | 例子 |
| --- | --- | --- |
| 当值用，放得进立即数 | **指令编码里**（`.text`） | `mov eax, 42` |
| 纯编译期用途（数组大小、模板参数） | **完全消失** | `int arr[K];` 只剩尺寸信息 |
| 被取地址 / 绑 const 引用 / 浮点数 | **`.rodata`** | `const int* p = &K;` |

### 4.2 只有被当对象用才占内存

```cpp
constexpr int K = 42;
const int* p = &K;          // 必须给真实地址
```

```asm
    .section .rodata
K:
    .long 42                ; 这里才第一次出现"内存"

    ...

    lea rax, K[rip]         ; 取地址
```

标准层面：`constexpr` 变量**是对象**，有存储期；
“没有存储”只是 `as-if` 规则允许编译器不物化，一旦观察地址就必须真实存在。

### 4.3 浮点常量几乎总在 `.rodata`

x86 的 `movss` / `movsd` 不能直接编码浮点立即数：

```cpp
constexpr double PI = 3.14159;
double g() { return PI; }
```

```asm
    movsd xmm0, QWORD PTR .LC0[rip]    ; .LC0 在 .rodata 里
```

即使没取地址也得落 `.rodata`。同理：64 位大立即数、SIMD 常量、字符串。

| 常量 | 通常在哪 |
| --- | --- |
| `constexpr int K = 42;` | 立即数（`.text`） |
| `constexpr double D = 3.14;` | `.rodata` |
| 字符串字面量 `"hi"` | `.rodata` |
| `enum` / `#define` | 不存在 |

## 5. 如何自己验证

```bash
size a.out                            # text/data/bss 各多大
objdump -h a.out | grep -E "rodata|\.data|\.bss"
objdump -d a.out | grep -A5 "<f>:"    # 看 sub rsp / mov eax, 0x2a
objdump -s -j .rodata a.out           # 看常量数据
nm -C a.out | grep -E "A::a|g1|g2"    # 符号所在段
```

`nm` 输出中符号后的字母含义：

| 字母 | 段 |
| --- | --- |
| `B` / `b` | `.bss`（未初始化静态区） |
| `D` / `d` | `.data`（已初始化数据） |
| `R` / `r` | `.rodata`（只读常量） |
| `T` / `t` | `.text`（代码） |

---

## 6. 速记

> **静态存储期**（全局、静态、静态成员）在**程序加载时**拿到内存，地址链接期就定；
> **自动存储期**（局部）在**函数入口**拿到栈空间；
> **动态存储期**在**运行时 `new`** 时拿到；
> **成员**不单独拿，随宿主对象；
> **常量**多半被编译器消掉，只有取地址时才落进 `.rodata`。
>
> 一句话：**分配是“拿到一块地”，初始化是“往地里种东西”**。
