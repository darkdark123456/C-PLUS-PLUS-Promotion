  在进行比较交换中，由于cpu架构的不同底层实现的也不同。
在ARMV8.0以下，比较交换指令不是由一条lock指令执行的，winx86 64架构下比较交换指令是由一条lock指令执行的，天然自带原子屏障操作，而ARM8.0以下需要监视器配合其他指令来完成原子操作，指令中间是有"缝隙"的。


#include <atomic>

std::atomic<int> h{0};
void func_(h.fetch_add(1,std::memeory_order_seq_cst));


//在arm cpu产生的汇编代码
retry:
    ldxr  w1, [x0]      ; ①
    add   w1, w1, #1    ; ②
    stxr  w2, w1, [x0]  ; ③
    cbnz  w2, retry     ; ④
    dmb   ish           ; ⑤

在理解指令之前，先了解指令的具体含义:
ldxr load exclusive register //独占的load寄存器 
    
stxr store exclusive register //独占的存储寄存器 
    
cbnz compare and branch if non-zero //比较交换分支。如果是非零 就继续跳回retry进行循环等待.
    
dmb ish data memeory barrier,inner shareable 
dmb 屏障。保证它之前的所有内存访问，在别的核看来都先于它之后访问完成
ish 作用域 位innershared able 共享同一级缓存的那一小群核，一般是一个cluster

   ldxr  w1, [x0]      ; ① //访存
    
  地址 0x4000 ~ 0x403F  ← 一条缓存行（64 字节）
  ┌────┬────┬────┬─────┬────┬────┐
  │ A  │ B  │ C  │ ... │    │    │
  └────┴────┴────┴─────┴────┴────┘
    ↑
  你的 4 字节 int 只占这里，但预订的是整条线
    
    从x0内存地址中读取4字节数据到w1，同时在独占监视器 exclusive monitor中登记这个地址。
    监视器在每个核心中只有一个，表示正在监控0x4000所在的cache line 一般为64字节，不是监视单个这个地址。一旦有其他核心的命令来写这个地址里的内容就作废，或者写同一条cache line中的其他地址，同样作废
    
    
    
    
    普通的w1=w1+1操作，普通语句，不涉及内存
    add w1,w1,#1 ②
    
    
    
    
    
    把w1写回[x0],但在写前，会先检查监视器 这条cache line，从①之     后有没有被别的核心写过？没被其他核心碰过 写入成功，并将w2=0 ，     被碰过，一个字节都    不写w2=1。成功还是失败的结果放在w2里。
    stxr  w2, w1, [x0]  ; ③ // 访存
	

   
    如果w2！=0 说明这条cache line 已经被其他核心修改过，
    此时的数据不是最新值，跳转到retry进行重新循环.
    cbnz  w2, retry     ; ④
    
    //如果不回退会怎么样？
    t1  核A: ldxr  → 读到 5             （预订了这一行）     
    t2  核B: 把值改成 6                 （A 的预订作废）
    t3  核A: add   → w1 = 5+1 = 6       （基于旧值算的）
    t4  核A: stxr  → 失败，w2 = 1       （线被改过，不写）
     
    //只有回退进行重新监视才会拿到最新的值
    t5  核A: ldxr  → 读到 6 （拿到最新值，重新预订）
    t6  核A: add   → w1 = 6+1 = 7
    t7  核A: stxr  → 成功，w2 = 0
                  内存 = 7  ✔ 两次递增都生效   
        
        
    
        
        
   //前面的对于内存地址里的内容读写保证被其他核心看到
  // 实际执行到此时，内存里的数据已经被成功更新了，已经是最新的数据了.
   dmb   ish           ; ⑤
